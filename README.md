# SK 울산 액체부두 · 3D 선박 운항 시뮬레이션

울산항 SK 1~8부두와 SK 2·3부이를 3D로 그리고, 유조선·케미컬선·LPG선이 입항부터 출항까지 실제 선박처럼 움직이는 모습을 시뮬레이션한다.

**모든 선박·선사·MMSI·화물·일정은 가상(목업) 데이터다.** 실행 중에 외부 API를 부르지 않는다. 데이터는 `public/js/data.js`에 고정되어 있고, 같은 시각에 열면 같은 장면이 나온다.

## 실행

```bash
cd sk-portwise
npm start            # 의존성 없음, Node 20+
# http://127.0.0.1:5050  (PORT, HOST 환경변수로 변경)
```

`public/`은 정적 파일만 있다. 아무 정적 서버로 열어도 된다. three.js와 글꼴은 CDN(jsdelivr)에서 받는다.

GitHub Pages: `main`에 push하면 `.github/workflows/pages.yml`이 시나리오 검증을 돌린다. 검증을 통과하면 `public/`을 그대로 배포한다. 처음 한 번은 Settings → Pages → Source를 **GitHub Actions**로 설정해야 한다.

## 선박이 움직이는 방식 (`public/js/sim.js`)

시뮬레이션은 three.js와 무관한 순수 로직이다. 브라우저와 Node에서 똑같이 돈다.

- **운동 모델**: 전후·좌우·선회의 3자유도.
  - 자력 항해: 1차 Nomoto 조종 모델(K = K'·U/L, T = T'·L/U)을 쓴다. 타각 속도는 2.5°/s로 제한한다. 타효는 선속에 비례한다. 저속에서는 프로펠러 후류와 예선이 보탠다.
  - 속력: 선형(길이)에 따른 시정수로 천천히 가감속한다. VLCC는 정지에 수 km가 든다.
  - 경로 추종: LOS(line-of-sight) 유도를 쓴다. 감속 거리는 미리 계산한다.
- **예선 보조**: 접안·이안·선회·부이 계류 때 쓴다. 예선 척수와 예인력, 선박 배수량으로 정한 가속도 한계 안에서 정해진 자세로 옮긴다. 예선은 경로망을 따라 이동한다. 항로에서는 예인줄로 호송하고, 선석 앞에서는 현측에 붙어 민다.
- **운항 절차**: 외해 → 도선사 승선 → 선석이 없으면 묘박지 투묘·대기(체선) → 예선 접선 → 선석 정횡 정렬 → 횡이동 접안 → 계류줄 → 로딩암 연결 → 양하·선적(흘수·트림 변화) → 로딩암 분리 → 이안 → 선회 → 출항 → 일정 시간 뒤 재입항.
- **교통 규칙**:
  - 항로 통항 분리: 진행 방향 오른쪽 차선으로 다닌다.
  - 같은 방향 선박은 앞 배를 따라간다.
  - 횡단·마주침: 우선순위가 낮은 쪽이 감속한다. 우선순위는 예선 보조 중 > 출항 > 입항이다. 정면으로 마주치면 서로 우현으로 비킨다. 추월하는 쪽이 피한다.
  - SK1·2부두 선회장은 한 번에 한 척만 쓴다. 이안은 선회 지점 주변이 비어야 시작한다.
  - 경로가 묘박 중인 선박 가까이 지나면 비켜 가는 점을 넣는다.
- **묘박·부이 계류**: 바람이 불어오는 쪽으로 선수를 둔다. 바람은 300° ± 18°로 9시간 주기로 돈다. 닻(부이)을 중심으로 흔들린다(sheer).

## 3D 표현 (`public/js/models.js`, `fleet.js`, `scene.js`, `effects.js`)

- 선체: 만곡부 반경, 선수 플레어·레이크, 구상선수, 트랜섬을 횡단면으로 이어 만든다. 만재흘수선 아래는 선저도료로 칠한다. 공선 때는 붉은 선저가 드러나고 선미 트림이 생긴다.
- 선종별 갑판:
  - 원유선: 굵은 배관
  - 석유제품선·케미컬선: 배관·탱크 해치가 많다
  - 가압식 LPG선: 원통형 탱크
  - VLGC: 트렁크 갑판과 돔
- 거주구·선교 날개·연돌·레이더(회전)·구명정·프로펠러(기관 지령에 따라 회전)·타(타각 반영)도 갖췄다.
- 파랑 운동: 외해 노출도에 비례한다. 횡동요 주기는 선폭으로 정한다.
- 등화: 마스트등·현등·선미등은 보는 방향에 따라 보인다(섹터). 그 밖에 정박등, 위험물 하역 홍등, 갑판 조명이 있다.
- 항적: 선미 난류와 켈빈파를 그리고, 예선이 밀 때는 추진류를 그린다.
- 줄과 하역 설비: 계류줄, 예인줄, 닻줄, 부이 계류삭과 해상 호스를 그린다. 하역 중이면 로딩암이 매니폴드로 뻗는다.

## 데이터

| 파일 | 내용 |
|---|---|
| `public/js/data.js` | 가상 선단 21척, 예선 6척, 시설·선석, 항로 노드, 묘박지, 07:30 시작 상태 |
| `public/data/coastline.json` | OpenStreetMap 해안선(© OpenStreetMap contributors, ODbL)을 시뮬레이션 영역으로 잘라 구운 육지 폴리곤 |

- 시설 위치와 수심·DWT 제원은 실제 SK 부두를 기준으로 했다. 선석 수와 배치는 시뮬레이션에 맞게 줄였다.
- 항로 노드는 울산항 제1항로 중심선 근처에 두었다. 묘박지 위치는 E1·E2·E3·W1 정박지 근처다.
- SK 2·3부이 좌표는 근사값이다.

해안선을 다시 구우려면 `node scripts/bake-coastline.js`를 실행한다. 개발용 1회성 도구라 Overpass API를 한 번 호출한다. 앱은 실행 중에 이 결과 파일만 읽는다.

## 시나리오 검증

```bash
npm run check                            # 72시간 헤드리스 실행
node scripts/check-scenario.js 24 --log  # 24시간 + 이벤트 로그 출력
```

헤드리스로 시뮬레이션을 돌려 다음을 찾는다. 하나라도 있으면 종료 코드 1을 낸다.

- 육지 침범(좌초): 선체 외곽점과 해안선을 비교한다.
- 선박 간 근접·충돌: 회전 사각형끼리 겹치는지 본다.
- 단계별 정체: 시간 한도를 넘긴 단계를 찾는다.

`data.js`의 노드·선석·일정을 고친 뒤에는 이 검증을 돌린다.

## 알려진 한계

- 조류·바람에 의한 표류와 얕은 수심 효과(squat)는 넣지 않았다.
- 부두 사이 거리는 실제보다 단순화했다.
- 접안 보조 구간은 예선 마력으로 제한한 운동학 모델이다. 유체력을 직접 풀지 않는다.
- 시각은 실행한 날의 KST 07:30에서 시작한다.
- 태양 고도와 밤낮은 실제 천문 계산을 따른다.
